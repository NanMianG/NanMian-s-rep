# 文案 → video-shot 分镜提示词

职责：把「一篇文案」变成「video-shot 能直接开工的提示词」。**只做策划，不写 HTML、不渲染。**

## 输入

- 文案文件路径（`.md` / `.txt` / 其它）：用 Read 读取；或用户直接粘贴的文本。
- 可选信息：受众、总时长 / 镜头数、画幅（默认横屏 `1920×1080`）、平台、语气。

## 工作流

1. **通读文案**，提取：主题、受众、钩子（开头抓人的点）、可视觉化的信息点（数字 / 对比 / 流程 / 因果 / 结论 / 情绪）。
2. **切镜头**：每镜只承载**一个**核心信息，8–15s。中文口播 ≈ **4.5 字/秒** 估时；可跑 `node scripts/pace.js <文件>` 得到字数与建议秒数。给每镜标**起止时间戳**、**口播原句**、**动效落点**（这一镜唯一的主视觉动作）与**留驻**（主揭晓后停多久）。
3. **排风格**：打开 `../video-shot/references/style-cards.md`，从 40 种里为每镜选一种。硬规则：
   - 相邻镜头风格 / 字体 / 配色不同，整辑不重复；
   - 风格与内容匹配（数字→报纸头条；账目→POS；概率→老虎机；流程→便签 / 线路图；对比→天平；收尾→明信片……）；
   - **同一实体 / 概念全片锁同一颜色**，方便观众跨页追踪；
   - 禁用默认科技暗色（黑底 + 霓虹 + 玻璃拟态），除非内容本身是终端主题。
4. **定动效与节奏**（详见 `../video-shot/references/style-cards.md`「动效与节奏」）：
   - **每镜只表达一个动效概念 + 一种情绪**；同一种动效手法（弹出 / 盖章 / 翻页 / 推进 / 擦除）全片只当一次主视觉；
   - 情绪**单向推进**：历史 / 反差 → 紧张 / 冲突 → 释放 / 落定，不来回跳；
   - 主揭晓「动作 0.45–0.6s + 留驻 0.5–1.0s」；批量入场 ≤0.5s；微状态 ≤1s；收尾约 1s；
   - 定稿前扫一遍全片，重复的动效手法与重复的 tagline 一律改掉。
5. **产交付物**：按 `references/prompt-template.md` 的模板，写入当前工作目录 `shotplans/<文案名>-shotplan.md`，并在对话里贴出。
6. **让用户确认分镜表**；确认后由用户 / 主 agent 用 video-shot 执行（提示词里已写好指令）。

## 交付物必须包含

- `【主题】【受众】【总时长 / 镜头数】【画幅】`
- 口播总稿（带时间戳）
- 分镜表：`# | 时长 | 起止 | 口播句 | 视觉风格 | 字体组合 | 主色 | 核心画面 | 动效落点(留驻)`
- 一段**可直接整段粘贴**给 video-shot 的提示词（以「用 video-shot skill……」开头，含输出目录、质检与出片要求）

## 硬性规则

- 口播**不上屏**（无字幕条），只作 cue 注释对齐；分镜表的「口播句」就是配 cue 用的。
- 数据 / 结论必须能给出处；无法核实的数字标注「待核实」，**不要编造**。
- 每镜要有明确落点（数字揭晓 / 对比结论 / 流程节点 / 情绪），避免「念稿」式空镜。
- **每镜一个动效概念**；全片动效手法不重复、情绪方向一致。
- 文案 >5 分钟时按章节分批出分镜，先给分批表再逐批细化。
- 复刻真实软件界面时，在「核心画面」里注明**用真实页面截图**，不要让 video-shot 手搓 UI 近似。
